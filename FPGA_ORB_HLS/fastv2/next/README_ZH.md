## FPGA/PS 分工及本轮删减

R4 将两份网格点缓存及其有效位收进单个 `consume_and_select` actor，该 actor 完成初始化、全部候选归约、回退选择、预算排序及 DDR 写回。DATAFLOW 不再把读写网格数组作为 PIPO 参数传出。两份点缓存明确使用 HLS `ap_uint<41>`，与原打包字段一致。R4 综合报告确认 R3 的 `[XFORM 203-713]` 警告消除；没有禁用依赖或屏蔽警告。但 R4 RTL 返回码检查失败，见下文。

R5 用独立的 8 位完成 FIFO 替代跨 DATAFLOW 的标量状态引用。消费者写完 DDR 摘要后恰好发送一个状态 token，顶层等待 DATAFLOW 返回后读取，并显式返回常量 0 或 4。FIFO 深度 2，允许消费者完成，不形成相互等待。非法配置在进入 DATAFLOW 前拒绝，不产生或消费完成 token。R5 已通过十一事务 RTL 重测，见下文；R6 只扩展图像核测试与入口，不改变三个核算法。

采用 FPGA 开发技能的分阶段验证：PL 承担全图的规律扫描、局部缓存、并行比较和定宽整数运算；现有 PS 后端只处理筛选后的点，方向与 A32 BRIEF 已改为整数计算和预生成采样表，运行时没有三角函数。R7 已实现板端调度器接入，尚待 SDK 构建及物理板验证。

- FAST 保持单像素扫描。16 组三点极值被重复使用来构成精确九点极值，不再为每个起点重复比较全部九点；像素差与极值使用有符号 9 位 HLS 类型，范围 -255..255，不改变减一响应。
- 候选点不再存为整帧数组，也不再整帧完成后重新查表归约。扫描时将已读出的网格编号和候选一起发入 FIFO，另一 DATAFLOW actor 直接更新高/低阈值赢家。声明的候选存储从 8192×8=65536 字节变为 128×8=1024 字节；这不是最终 BRAM 报告。
- 删除 8192 候选上限：它原本来自整帧缓存容量，而流式归约不需要这个限制。新分支对密集画面仍输出完整候选数和 CPU 一致的选中点；原基线及其错误码枚举不改。
- 网格存储按冻结配置最大 204 个单元声明，而不是 256。低阈值赢家存储在归约后原位用作最终赢家，强度排序直接消耗其有效位，删除第三份赢家数组及重复的 winner_valid/emitted 数组。
- Gaussian7 保留五阶段 DATAFLOW 和七个行缓存。利用核系数对称性，先将对称采样相加，把七个常系数乘积改为四个，最终才舍入。行槽编号用递增/比较代替模七；反射后的七个行槽映射每行只算一次，像素循环禁止展平，不再每像素重复映射。行缓存改为一读一写 RAM_S2P，保持当前写入的显式旁路。FIFO 改为静态实例，像素总数在 DATAFLOW 区外计算；是否消除原工具警告需查看 R3 日志。
- resize 保持双像素插值与四列分银行缓存。冻结轴记录中的 b 始终等于 a+1，新增全表测试后不再读取冗余的 b 字段。非负插值中间数最大 66846720，使用 32 位代替 64 位；保留所有原来的逐级移位及舍入，不改成近似插值。

低阈值回退、瓦片边缘 NMS、强度/同分排序、反射边界、输出容量检查、末字补零都保留。它们影响算法结果，不能因为某一真实帧没触发就删除。

## 计算与接口合同

器件 `xc7z015clg485-2`，PL 10 ns。目标为 FAST RasterColumns 单像素 II=1、resize 双像素插值 II=1、高斯主要像素阶段 II=1。AXI-Lite 函数、16 字节点及 64 字节结果布局不变，合法尺寸/预算仍为原八层冻结配置。

候选 FIFO 为单生产者/单消费者，深度 128；点占 token 的 0..40 位、网格编号占 41..48 位，最后一个 token 置位 63 并携带完整候选数。消费者初始化全部网格、持续消费到结束标记；阻塞读写提供无丢失反压。归约存在同单元读改写依赖，不强行声明 II=1、不伪造 DEPENDENCE false。

高斯 raw/horizontal/blurred FIFO 深度各 64，packed 深度 16。三个像素通道各产生/消费 width×height 个 token，字通道各 ceil(width×height/8) 个。输入输出图像均为紧密行排列的 little-endian 64 位打包，仅图像末尾允许补零，缓冲区必须互不重叠。

主机适配器为无界队列，检查数值与 token 数量，不模拟有限 FIFO 的反压、死锁、复位或 AXI 等待。resize 仍按行装载、插值、打包、写回，不是整核 DATAFLOW；高斯读块/解包及收块/写回在各自 actor 内仍顺序执行。

## 后续验收及生成边界

默认 HLS 入口隐藏后台运行，立即返回 PID/日志。每次创建独立 `hls_build/jobs/<时间_选择_唯一编号>/`，冻结输入与 SHA-256，不复用或删除旧输出。新任务版本标记 `image_regression_r6`。不带 `-Cosim` 时 PASS 只表示工具完成；带该参数还要求上文 RTL/警告检查，均不表示资源/时序或整帧性能验收。启动综合后不持续轮询。

尚需 R6 图像核全尺寸 RTL 验证、有限 FIFO 反压覆盖、R7 三核 Vivado 正式构建与 SDK 验收、真实板端 PS 调度/计时及 100～1000 帧平均耗时测试。HLS 回归入口不导出 IP、不布线、不操作 JTAG；R7 构建入口单独负责 IP/布线/SDK，也不会自动操作 JTAG。

`host_build/`、`hls_build/`、`include/backend_tables.h`、`ps/full_reference.inc` 为生成产物，不手工修改。基线 bit/ELF 的 SHA-256 本轮核对保持不变。
