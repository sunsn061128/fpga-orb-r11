# FPGA ORB 参考方案核对与迁移结论

## 1. 结论

参考工作的高帧率主要来自像素流式结构，而不是改变某一个 C 函数：输入像素通过行缓存和窗口缓存复用，FAST、NMS、Gaussian、方向及描述子在同一条流水线上工作，避免把每个中间图像写回 DDR 后再读出。

当前工程必须保持 v1.0 参考结果逐字节一致，因此只迁移结构优化，不采用会改变结果的算法近似。

## 2. 性能数字不能直接横向比较

| 方案 | 报告性能 | 与本工程的主要差异 |
| --- | --- | --- |
| Fang 等，FPT 2017 | 640×480、两层、203 MHz、14.8 ms/帧 | Stratix V；方向字长截断到 8 位；算法结果不要求与本工程一致 |
| Vemulapati 与 Chen，2022 | 640×480、四层、150 MHz、系统 62 FPS | ZU3EG；6 位像素、64 个角度区间、替换 Gaussian 核；描述子单元忙时允许丢点 |
| Siudya/ORB_FPGA | 640×480、140 MHz、17.56 ms/帧 | XC7Z020；固定阈值 20、单尺度、无本工程的双阈值与网格配额；输入图像由两个 DMA 重复发送 |
| Wasala 等，Electronics 2022 | 3840×2160@60、150 MHz、4 ppc | ZCU104；RS-BRIEF；不做 Harris 排序和最佳 N 点选择；算法已经修改 |
| Thoma 等，J. Imaging 2025 | 1920×1080@60 输入 | 不计算方向，BRIEF 不旋转，并为每个像素并行生成描述子，目标算法不同 |

因此，本工程的验收口径仍固定为：960×720 输入、八层金字塔、完整 v1.0 语义、平均每帧处理时间低于 33.33 ms，并同时报告连续多帧稳定性。

## 3. 可以迁移的结构

1. 使用环形行索引，不在每个新行到来时搬移整行数据。
2. 使用 `LOOP_FLATTEN off`，避免 Vivado HLS 2018.3 对运行时宽度的嵌套循环生成大规模除法/取模电路。
3. FAST 的 16 个圆周差值及 9 连续点判断并行计算，目标吞吐量为一个像素一个周期。
4. FAST 分数后紧接两行分数缓存和 3×3 NMS，不把整幅分数图写回 DDR。
5. Gaussian 使用 7 行缓存和可分离卷积；保留本工程冻结的 `[18,34,48,56,48,34,18]` 核及舍入规则。
6. 方向矩使用滑动列和递推更新；保留半径 15 圆形掩码、完整精度和现有 32-bin 量化结果。
7. 描述子通过 FIFO 与像素流水解耦；若描述子端忙，必须反压或排队，不能像部分论文那样丢点。
8. 最终接口改为 AXI4-Stream/AXI DMA；PS 只负责帧缓冲、寄存器配置、结果回读和性能统计。

## 4. 不采用的近似

- 不把 8 位像素截断为 6 位。
- 不替换 Gaussian 核。
- 不把方向改为论文的 64-sector 近似。
- 不改成 RS-BRIEF 或不旋转的 BRIEF。
- 不允许描述子单元繁忙时丢弃候选点。
- 不改变严格大于的 NMS 相等分数规则，也不取消 tile-local 边界语义。

## 5. 当前迁移顺序

1. 先消除 HLS 自动生成的运行时除法器，使 FAST 行缓存版本重新满足 XC7Z015 资源约束。
2. 把 FAST 与 tile-local NMS 融合成流式阶段，并以现有 172 组向量逐项回归。
3. 把精确 Gaussian 改为流式可分离卷积。
4. 将方向矩改为滑动递推，描述子改为队列化流水。
5. 优化 resize，并将八层调度纳入 960×720 连续 100～1000 帧板级测试。

每一步都必须同时通过主机回归、C/RTL 协同仿真、综合资源/时序检查和板级摘要回读，才进入下一步。
