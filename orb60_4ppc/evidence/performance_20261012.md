# 4PPC 性能诊断：PS 与 PL

依据已接受的 normal Production 各 100 帧数据、实际编译的两版 board.c 和 2018.3 HLS 报告。两版相邻 normal Verified 100 帧均通过精确比较；Production 自身标记为 COMPLETE_UNVERIFIED。本次没有重新上板或改动设计、ELF、bit、已接受发布包。

PS 没有出现新退化：两版 CPU 配置、PS 初始化和缓存/调度方式一致，descriptor(n) 与 image(n+1) 确实并行。PS 在处理阶段的额外调度没有形成毫秒级空洞。不过现有程序每帧复制 691200 字节输入并刷新缓存，连同准备和循环管理约 2.69629 ms，占循环总时间 22.25%。因此 PS 输入路径确实限制整帧吞吐，不能笼统说完全没有开销。

| --- | ---: | ---: |
| 程序循环 / 帧 | 14.39856 | 12.11829 |
| 输入准备及循环管理 / 帧 | 2.70856 | 2.69629 |
| 处理 / 帧 | 11.69000 | 9.42200 |
| PL 计数重建的理想调度路径 / 帧 | 11.55856 | 9.30321 |
| 处理与理想调度路径差值 / 帧 | 0.13144 | 0.11879 |
| 缓存维护 / 帧（包含在上面的时间内） | 1.04693 | 1.04624 |
| 寄存器配置 / 帧（包含在上面的时间内） | 0.03917 | 0.03918 |

缓存和寄存器时间包含在输入准备或处理中，不能再次相加。输入准备数字为循环总时间减平均处理时间，其中还包含少量循环管理；未分别测量 memcpy、输入 flush 和 metadata。处理差值也包含硬件收尾、stats 写回和计数口径差异，不能将它全称为 CPU 时间。

整帧程序循环吞吐从 69.45 增至 82.52 FPS；处理时间对应 85.54 与 106.13 FPS。消除现有输入准备开销而保持 PL 不变，只能接近 106.13 FPS。140 FPS 要求全帧 7.14286 ms，当前处理阶段自身仍超过这一目标。

在 100 MHz 下，根据每核计数重建调度：T = I0 + Σ(l=0..6) max(Dl, I(l+1)) + D7。4PPC 的每个 Dl 都长于与之并行的下一层图像核，因此路径变为首层图像 2.28644 ms + 八层描述子 7.01677 ms = 9.30321 ms，与实测处理 9.422 ms 接近。这里不能把所有图像时间与所有描述子时间直接相加。

八层描述子合计从 5.29540 增至 7.01677 ms，增加 1.72137 ms（32.51%）。最后一层没有图像核并发，描述子仍变慢，因此不能仅用两个核争用 DDR 解释全部变化。

明确的实现开销位于 scripts/migrate_descriptor.py：旧实现通过 stream_of_blocks 的 write_lock/read_lock 直接共享 patch 存储；2018.3 兼容实现先输出 64 位字 FIFO，再在 compute_descriptors 中执行 CollectRawPatch（158 拍）与 CollectBlurPatch（222 拍），然后才运行描述子运算。真实 HLS 报告证实两个收集循环 II=1，合计 380 拍/点；280 点对应 1.064 ms 的本地复制工作。该工作位于消费者的串行路径，但不能直接认定删除后会节省相同整帧时间：加载和计算的重叠、FIFO 背压和 DDR 等待会改变限制因素。生产者每行也串行清零、DDR 读取、FIFO 输出，增加请求间隙。

四路图像的 FAST/NMS、Gaussian、Resize 主循环均已达到 II=1；首层实际仍为 228644 拍，理想 960×720/4 为 172800 拍。其余开销包括行准备、流水线填充/排空、候选串行合并、选点和 AXI 等待。normal 的各层点数均小于预算，使用 EmitCellOrder，不执行 EmitStrengthOrder 的全网格反复排序；不能用该排序分支解释本次 normal 性能。

结论：PS 配置和调度没有新增明显退化，输入准备有稳定的约 2.70 ms 开销；当前处理关键路径主要落在 PL 描述子，2018.3 兼容 patch 传递引入了确定的本地复制开销。既有 PL 计数包含 DDR/AXI 等待，尚不能量化内部运算和平台访存各占多少。两版 PL 工具版本和 patch 传递实现同时变化，不能将描述子增长归因于工具版本本身。

后续优化应先让 patch 加载与描述子计算通过双缓冲 RAM 重叠，减少 FIFO 到 RAM 的串行搬运，并用精确比较和实际 DDR 板测检查收益；现有 Slice 占用已达 100%，需要同时核查资源和路由。PS 侧可进一步优化输入所有权交接和缓存维护，减少每帧复制；必须保持缓存一致性。
